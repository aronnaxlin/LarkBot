# LarkBot 项目讨论记录

日期：2026-10-16

本文记录本次讨论的需求、已确定方向、技术建议与待确认事项。除明确标注的决定外，方案均未实现，不代表已经完成选型或验证。

## 1. 产品目标与需求

做一个由 LLM 驱动、模块化、飞书（Lark）优先的群聊吹水机器人，保留未来接其他聊天平台的能力。

它不是个人助手，不是工具执行人，不以生产力为目标。它以群成员的方式参与聊天，有稳定的人设、自我身份和兴趣，也具备基本 Agent 能力，可以为自己需要的信息执行 Bash、操作浏览器和查询外部内容。

用户明确提出：

- 支持提及后回复的模式，以及持续旁听群消息、自主判断是否参与的模式。
- 能识别 @、叫名字、引用回复等参与信号，但有拒绝回答的权利。
- 有长期记忆和人设，分清消息发送者是谁。
- 对管理者与普通用户都维护逐人记忆文件。
- 维护主人／维护者列表。
- 第一批接入飞书 Skills／MCP 等能力，获得权限范围内较全面的群聊上下文。
- 不需要多对话管理，但需要上下文压缩。

讨论中的实现原则：唤醒不构成发言承诺；机器人在思考、使用工具后，仍可沉默，也可仅作表情回应。自主查资料与对群发言应可分开。

## 4. 菜花的强制发言机制

### 当前行为

1. 每次正常唤醒先运行外部判断者 Probe；被中断工具循环的续跑例外。
2. Probe 通过 `decide` 返回 `send_message` 或 `no_action`；无效结果默认不激活。
3. `no_action` 表示不发消息、不作表情、不调用工具。
4. Primary 激活后可以调用工具，但必须至少执行一次 `send_message`。
5. 若循环结束仍未发送，`src/driver/wakeup.ts` 会执行 forced-send fallback，强制选择发送工具。

因此准确表述是“激活后强制发言”，不是“每条群消息必须回答”，也不是“必须满足请求”。它仍可以发消息拒绝。

### 我们要的差异

- Probe 是是否值得唤醒的门槛，不是发言承诺。
- Primary 可在查资料后决定不说，也可只作表情。
- @ 是强参与信号，不等于必须服从。
- 要同时处理系统提示词与程序 fallback，不能只换人设。
- 具体结束工具和终止状态如何设计，实施时结合现有 runner 决定。

## 5. Hermes 的已知痛点与执行约束

用户反馈：目前用 Hermes 做这件事，处理群聊消息问题很大；已明确列出的第一项是无止境工具调用、回复很慢。尚未提供调用日志，根因未定位，不能归因于某个具体 Hermes 模块。用户可能还有其他问题尚未列出。

菜花不能原样保证解决：已检查的唤醒代码给主循环设置了 `maxSteps: Infinity`。

### 拟采用的方向，参数尚未确认

- 普通闲聊优先直接回应或沉默，工具按需使用。
- 程序预加载近期聊天和参与者的精简记忆，避免模型每轮逐人查档案。
- 同时限制工具轮数、调用总数、单工具超时和整轮期限。
- 初始讨论值：最多 2 轮工具执行、共 4 次调用、整轮约 15 秒；仅为调试起点，需要按真实模型延迟调整。
- 预算耗尽后停止工具执行，剩余预算允许时进行无工具收尾，可发言也可沉默；不要用强制发言兜底。
- 新消息不得重置当前轮预算，不能无限续长工作。
- 合并突发消息，避免为每条群消息积压独立回复任务。
- 发言前检查上下文是否过时，话题变化时可丢弃不再适合的回复。
- 慢查询可后台处理，但不要求每个后台任务都向群里汇报。
- 中断须遵守副作用与持久化一致性，不能在工具执行后、记录保存前随意中止。

Jev 只能减少不必要的唤醒，不能解决主循环里的无限工具调用。

## 7. 长期记忆：Nowledge Mem 与 Mem0

### 已核实的定位

- Nowledge Mem：完整的知识与上下文产品，有对话、记忆、图谱、身份上下文与管理界面；已支持 Docker 无头部署、REST／MCP／CLI，不能简单视作桌面个人笔记软件。
- Mem0：应用可编程记忆组件，有托管版与 OSS；能力须按版本区分。OSS 仓库为 Apache-2.0。
- Nowledge 当前公开仓库未提供完整核心实现，不能当作已有完整开源底层；具体许可和价格需另确认。

### 讨论建议，不是最终决定

若更重视自定义群友认识和写入策略，倾向 Mem0 OSS；若更重视开箱即用的记忆审阅、图谱和管理体验，Nowledge Mem 值得验证。未进行同数据对比，不宣称任何一家记忆效果更好。

此前提出 Mem0 OSS + Qdrant、暂不开图记忆；在决定复用菜花后，进一步明确它不应成为第一阶段前置依赖，可先补逐人文件和最小记忆流程。

### 无论选谁都必须实现的边界

- 区分说话者、记忆描述对象、本人自述／他人转述／机器人印象。
- 保存来源消息、群、时间和可见范围。
- 稳定平台 ID 由程序解析，不能按昵称认人；跨平台身份不自动合并。
- 维护者权限来自可信配置，不从聊天内容或记忆推断。
- 管理者和普通用户都维护人物记忆，权限另外计算。
- 支持纠错和删除；跨群传播个人信息不默认开放。
- 数据范围由程序约束，模型传入过滤参数不是授权。
- Mem0 不同向量后端过滤语义有差异，需要对实际选用后端测试隔离。

### 文件与存储建议

- `identity.md`：自我身份与经历边界。
- `persona.md`：性格、兴趣与表达习惯。
- `maintainers.yaml`：可信维护者列表。
- `memory/users/<stable-id>.md`：逐人可读画像。
- `memory/groups/<chat-id>.md`：群文化、共同经历与梗，按需增加。
- 原始事件、工具记录、上下文压缩摘要保留在 SQLite。

若接 Mem0，须明确单一权威写入流程，避免人物文件和 Mem0 双向任意修改导致冲突。群聊摘要与人物长期记忆分工不同，不能互相替代。

## 8. Jev 是否值得接

结论：值得作为 Probe 替代候选测试，不在现有 Probe 前后再堆叠一个判断层，也不作为权限判断器。

拟判断的问题是“现在是否值得唤醒机器人进一步参与判断”，不是“是否必须回答”。可以用 Noul 输出是的概率，或按需要采用 Choice；第一版不做多维评分系统。

输入应包含近期带发送者与引用关系的聊天、精简人设和兴趣、当前参与状态、最近发言情况及必要关系摘要，不只给最后一句。

曾提出明确 @／回复可直接唤醒、普通旁听交给 Jev；这属于候选策略。菜花当前所有正常唤醒均经过 Probe，是否绕过须在改动时明确决定。

官方文档提示英语为主要训练语言，CJK 表现需自测。中文反话、谐音、昵称和群内梗必须用真实脱敏数据验证，不能先假定优于普通小模型。

评估维度：漏掉该接的话、无谓插话、端到端延迟、主模型唤醒比例及总费用。阈值用数据调，不直接照搬示例；概率不是回应一定受欢迎的保证。

调研时文档标价为每百万输入 token 0.042 美元、输出免费，仅为当时价格。示例：每天 10,000 次、每次 3,000 输入 token，Jev 约 1.26 美元／天，不含其他成本。还须考虑向额外服务商发送群消息的隐私影响。

参考：https://docs.typesafe.ai/models.md

## 9. 飞书能力与安全边界

- 使用开放平台应用机器人，不是只有推送能力的群自定义 Webhook。
- 持续监听依赖事件订阅，不让模型通过 MCP 高频轮询。
- 按 AstrBot 飞书接入文档，全群消息需开通 `im:message.group_msg`，并完成事件订阅、版本发布和入群。
- 官方 CLI／Skills、MCP 可补查历史、引用、成员、资源；它们不能突破应用权限及接口可见范围。
- 入群前历史、外部群、成员信息和附件能力需在实际租户验证。
- 飞书与国际版 Lark 的域名／环境选择需实现时核实。
- 机器人发言身份与维护者用户授权身份分开，不能无意代维护者发言。
- Bash 与浏览器必须实际隔离；提示词写着 Docker 不等于代码具备沙箱。已检查的菜花 Bash 实现执行的是配置 shell。
- 执行环境不挂宿主机敏感目录、SSH 密钥或维护者私人浏览器资料；不把飞书密钥与权限配置暴露给模型任意修改。
- 第一版不开踢人、删消息等无关管理权限；保留上游代码不等于启用功能。

## 10. 建议实施顺序

### 第一阶段：可用且有边界的飞书群友

1. 用户已确认私下取得授权；后续开发、分发与公开范围遵守实际授权条款。
2. 飞书接收、归档、稳定身份、@、引用与发送，复用现有 pipeline。
3. 允许合法沉默和仅表情结束，修改相关提示词、执行约束和测试。
4. 为工具循环增加有界执行，处理新消息下的收尾与持久化一致性。
5. 配置人格和维护者，明确两种参与模式。
6. 验证重启恢复、去重、身份归属、沉默结束和预算耗尽。

### 第二阶段：人物长期记忆

实现逐人记忆、证据归属、纠错与范围限制，再决定是否接 Mem0／Nowledge。

### 第三阶段：扩展能力与调优

接隔离浏览器、飞书 CLI／Skills／MCP；用脱敏聊天对比 Jev 与原 Probe 后再决定替换。
